# 導入手順
1. Supabase SQL Editor で `previous_live_update.sql` を実行（既存 setup.sql, update.sql, entry_rules_update.sql の後）。
2. index.html と audition.js を既存ファイルに上書き。app.js と style.css は変更なし（同梱は参考用）。
3. 前回ライブの結果公開済みオーディション詳細で、部長が「実際の出演バンド」にチェック。
4. 新しいオーディション作成時に「前回ライブ」を選択して作成。
5. 受付中のエントリーで同一バンドIDはサーバー側で拒否。3人以上重複禁止と締切前取消も継続。

注意：前回ライブを指定せず作成した場合、前回出演制限はかかりません。公開済みライブの出演履歴は、次回オーディションが受付開始した後は変更できません。
注意：1年生バンドの定義は暫定（締切年と入学年度の一致、全員）。正確な定義の確認後に改修が必要です。
注意：ライブの出演履歴は結果公開済みのオーディションに紐づけます。エントリーだけでは出演扱いしません。
